# 测试

> 状态：v0.1 已实现 ｜ 更新：2026-11-01

测试代码在 `tests/`，用例名即编号来源；本文只记录**策略与门禁**。

## 1. 测试策略

| 层级 | 范围 | 手段 | 频率 |
|---|---|---|---|
| 单元测试 | 纯逻辑：配置解析与校验、编码识别、日志写入/轮转/回退 | doctest + ctest | 每次提交 |
| 集成验证 | 注册表读写、广播、托盘、单实例、自启 | 真实桌面手工执行 | 每个版本 |
| 手工验收 | 交互、异常、多环境 | 见 §3 矩阵 | 发布前 |

原则：能进单元测试的逻辑不要放到手工测试里；依赖 Windows 交互的部分接受手工验证，但必须有清单。

单元测试只链接 `src/` 下的纯逻辑源文件，不链接 `main.cpp` / `tray.cpp` / `menu.cpp` 等依赖窗口的模块，因此可以脱离桌面运行。

## 2. 覆盖范围

v0.1 只覆盖配置与日志；`solar` / `scheduler` / `hotkey` / 状态机的用例随 v0.2 模块引入。

| 模块 | 测试点 |
|---|---|
| `config` | 默认值、缺失键、非法枚举与非法值、损坏文件、UTF-8 BOM 与无 BOM、便携路径 |
| `logger` | 写入格式、轮转与保留份数、主路径不可写时的回退 |

## 3. 用例编号

| 编号 | 场景 | 期望 |
|---|---|---|
| TC-CFG-01 | 空文件 | 返回默认配置 |
| TC-CFG-02 | `mode=purple` 或 `mode=auto` | 回退 `light` 并记录日志 |
| TC-CFG-03 | 截断 / 乱码文件 | 备份为 `.bak.<时间戳>` 后重建默认配置 |
| TC-CFG-04 | UTF-8 BOM | 正确解析 |
| TC-CFG-05 | 无 BOM UTF-8 | 正确解析 |
| TC-CFG-06 | exe 同目录存在 `portable.ini` | 配置写到 exe 同目录 |
| TC-CFG-07 | 非法时间、超范围经纬度 | 对应键回退，其他键保留 |
| TC-LOG-01 | 正常写日志 | 含时间、级别、正文，每条落盘 |
| TC-LOG-02 | 超过 256 KB | 轮转，保留 3 个历史文件 |
| TC-LOG-03 | 主路径不可写 | 回退到 exe 同目录 `logs/` |

v0.2 补充：`TC-SOL-*`（日出日落）、`TC-SCH-*`（调度）、`TC-HK-*`（热键解析）、`TC-STM-*`（状态机）。

## 4. 手工测试矩阵

### 环境维度

| 维度 | 取值 |
|---|---|
| 系统 | Win10 22H2、Win11 22H2 / 23H2 / 24H2 / 25H2 |
| 架构 | x64、ARM64（如有设备） |
| DPI | 100% / 125% / 150% / 200% |
| 显示器 | 单屏、双屏不同 DPI |
| 主题 | 浅色、深色、应用与系统不一致 |
| 会话 | 本地、远程桌面 |
| 权限 | 普通用户、管理员 |
| 路径 | 含空格、含中文的安装目录 |

### 功能清单

- [ ] 左键单击切换，300 ms 内变色且图标同步
- [ ] 右键菜单：状态摘要正确、单选/复选正确、点击外部关闭
- [ ] 深色系统下菜单为深色（`uxtheme` 不可用时回退）
- [ ] 单实例：第二次启动只弹菜单，不出现第二个图标
- [ ] 开机自启：勾选写入、取消删除、外部删除后菜单显示未勾选
- [ ] 配置改后重启生效；便携模式配置落在 exe 同目录
- [ ] 退出：图标消失、进程结束、配置已保存
- [ ] 100% / 150% / 200% 下图标清晰，改缩放后自动重载
- [ ] 配置损坏、目录只读两种异常路径不崩溃

### 稳定性

- v0.1 门禁：连续运行 3 天无崩溃、无持续内存或句柄增长；7 天为目标。
- 切换 1000 次后句柄与 GDI 不持续增长。

## 5. 门禁

CI 中失败即阻断：`/W4 /WX` 零警告、单元测试全过、clang-format 无 diff、clang-tidy 无 error、依赖仅系统 DLL。

体积不设门禁：CI 只记录每次构建的体积作为版本间基线，明显膨胀在评审时说明。

## 6. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 崩溃、无法切换、破坏系统设置 | 立即修复，阻断发布 |
| P1 | 功能不可用但有绕过方式 | 本版本修复 |
| P2 | 体验问题、偶发异常 | 排期修复 |
| P3 | 文案、视觉细节 | 可延后 |

## 7. 发布前的测试侧条件

- 主路径（系统 × 主题 × DPI）全部通过，异常路径（配置损坏、目录只读）通过。
- 3 天稳定性完成；7 天目标未达时在 Release 说明里写清楚。
- 体积、内存、启动耗时已实测并写入 [构建 §8.1](06-build.md#81-实测数据)。

其余发布检查项见 [交付 §5](08-delivery.md#5-发布检查清单)，不在这里重复。
