# 主题切换机制

> 状态：v0.1 已实现 ｜ 更新：2026-11-01

实现见 `src/theme.cpp`。本文只记录系统层的约束与取舍。

## 1. 原理

Windows 的浅色 / 深色由当前用户注册表中的两个 DWORD 决定；修改后向所有顶层窗口广播 `WM_SETTINGCHANGE`（主题名 `ImmersiveColorSet`），系统组件与应用程序据此刷新配色。

没有公开的 `SetSystemTheme` API，注册表加广播就是系统设置页本身的做法。

## 2. 注册表位置

```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize
```

| 值名 | 含义 | 浅色 | 深色 |
|---|---|---|---|
| `AppsUseLightTheme` | 应用主题 | 1 | 0 |
| `SystemUsesLightTheme` | 系统主题（任务栏、开始、通知中心） | 1 | 0 |

只读写这两个值。不碰同键下的其他值（如 `EnableTransparency`），也不修改 `CurrentTheme` 或 `.theme` 文件。

## 3. 读写与广播的约定

- **每次切换前重新读**，不用内存值决定"取反"目标；用户在系统设置里改过之后，缓存必然错位。
- 值缺失或读取失败视为浅色（系统默认），只记 `warn`，不阻断切换。
- 先写应用主题，再写系统主题；任一失败则回滚已写的值、**不广播**，返回失败。
- 写入后立即广播，不延迟、不合并。
- 广播用 `SendMessageTimeoutW` 而非 `SendNotifyMessage`：需要等窗口处理完，并且能对无响应程序设上限。`SMTO_ABORTIFHUNG` 防止一个挂起的程序拖住整条链路。
- 广播超时视为注册表已改成功，只记日志。
- 写后读回不一致：记日志，以注册表实际值为准刷新界面。

## 4. 时序

```
点击
 ├─ 读 AppsUseLightTheme ──► 当前 = 浅色
 ├─ 写 AppsUseLightTheme = 0
 ├─ 写 SystemUsesLightTheme = 0
 ├─ 广播 WM_SETTINGCHANGE("ImmersiveColorSet")
 │    ├─ Explorer：任务栏、开始菜单、通知中心
 │    ├─ Chromium 系：窗口配色
 │    └─ 其他应用：各自处理
 └─ 刷新托盘图标与菜单
```

## 5. 状态判定

| 应用主题 | 系统主题 | 界面展示 |
|---|---|---|
| 深色 | 深色 | 深色 |
| 浅色 | 浅色 | 浅色 |
| 深色 | 浅色 | 深色（应用）/ 浅色（系统） |
| 浅色 | 深色 | 浅色（应用）/ 深色（系统） |

混合状态下，切换以**应用主题**为基准取反，并同时写入两者（`include_system_theme=1` 时）。

托盘图标只跟随**系统主题**，菜单状态摘要同时展示两者。这条规则的原因见 [托盘图标设计 §7](../product/06-icon-design.md#7-状态映射)。

## 6. 边界与已知问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 部分旧 Win32 程序颜色不变 | 只在启动时读主题 | 文档说明；不重启进程 |
| UWP / WinUI 应用未刷新 | 应用自身缓存 | 文档说明 |
| 高对比度下切换无效 | 系统优先使用对比度主题 | v0.2 的 F-10 检测到即禁用 |
| 远程桌面会话 | 主题按会话隔离 | 正常支持，无需特殊处理 |
| 用户手动在设置里改主题 | 状态被外部修改 | 监听广播刷新界面；v0.1 不重载图标 |

明确不做：

- 不重启 `explorer.exe`。
- 不调用未文档化的 `SetSystemTheme` 类接口。
- 不修改 `.theme` 文件或 `CurrentTheme`。

## 7. 性能与安全

- 单次切换的注册表操作加广播通常 < 30 ms；广播上限 5 秒属于极端兜底。
- 不申请管理员权限；即使用户以管理员身份运行，也只操作当前用户的 `HKCU`。
- 不创建服务、不写计划任务、不修改系统策略。
