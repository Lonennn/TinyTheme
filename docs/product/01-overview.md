# 产品概览

> 状态：草案 v0.1 ｜ 更新：2026-11-01

## 1. 背景

Windows 11 切换浅色 / 深色主题只有一条路径：

```
设置 → 个性化 → 颜色 → 选择默认应用模式 → 浅色 / 深色
```

系统没有提供快捷键，快速设置面板不对外开放第三方磁贴，命令行也没有直接入口。对一天要切换数次的人来说，这条路径太长。

## 2. 问题定义

**高频、低价值、路径长的系统设置操作。**

| 维度 | 现状 |
|---|---|
| 频率 | 换环境光、进入夜间、演示前后，每天 1–5 次 |
| 单次价值 | 操作本身零价值，纯摩擦 |
| 单次成本 | 约 6–10 秒，且需要离开当前工作上下文 |
| 失败模式 | 忘了切，或者切完忘了切回 |

## 3. 现有方案与空白

| 方案 | 优点 | 不足 |
|---|---|---|
| 系统设置 | 无需额外安装 | 路径长，无快捷键 |
| PowerToys Light Switch | 官方维护，支持定时与快捷键 | 需要安装整套 PowerToys，体积与常驻开销大 |
| AutoDarkMode | 功能最全，可联动壁纸、强调色 | .NET 应用，安装包与内存占用偏高 |
| 原生快速设置开关 | 最顺手 | 截至本文档编写时仅在 Insider 预览通道出现，尚未全面可用 |

空白：**一个不用安装、不驻留大依赖、点一下就走的小工具。**

## 4. 定位

TinyTheme 是"主题开关"，不是"主题管理器"。

- 只做一件事：让当前主题在浅色 / 深色之间切换，并且足够快。
- 形态：托盘常驻（v0.1）+ 全局热键（v0.2）+ 可选定时（v0.2）。
- 体积：单文件，保持轻量（目标几百 KB 量级，不设硬性上限），常驻内存 < 10 MB。

## 5. 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-1 | 一次点击完成切换 | 从点击到桌面完成变色 < 300 ms |
| G-2 | 不打断当前工作 | 全程不需要打开任何窗口 |
| G-3 | 极低存在感 | 常驻内存 < 10 MB，空闲 CPU 0% |
| G-4 | 零安装成本 | 解压即用，不需要管理员权限 |
| G-5 | 可预期 | v0.2 自动模式下不出现"该切没切"的情况 |

## 6. 非目标

- 不做主题包管理，不修改 `.theme` 文件，不替换系统强调色（v0.3 之前）。
- 不注入 Explorer，不 hook 系统进程，不修改 HKLM。
- 不做云同步、账号体系、遥测上报。
- 不做多用户管理与企业策略下发。
- 不覆盖 Windows 10 之前的老系统。

## 7. 目标用户

1. **长时间在电脑前的开发者**：白天浅色、夜间深色，或反过来。
2. **对光线敏感的用户**：需要随时快速切到深色，不固定时间。
3. **演示 / 截图 / 录屏用户**：临时切换后要能快速切回。

## 8. 价值主张

> 一个轻到几乎忘记它存在的图标，点一下，世界就换了颜色。

## 9. 成功指标

定性：

- 自己连续使用 30 天，不再打开设置页切换主题。
- 新用户首次运行后 10 秒内完成第一次切换，不需要读文档。

定量（不做遥测，只能通过 GitHub 与用户反馈收集）：

| 指标 | 目标 |
|---|---|
| 崩溃相关 issue | 发布后 3 个月内为 0 |
| 平均常驻内存（用户反馈） | < 10 MB |
| 下载到首次运行的流失 | 无法精确统计，用"首次运行即可用"的设计规避 |
| 卸载残留 | 仅保留配置目录，删除 exe 即视为卸载 |

## 10. 约束

- 仅使用公开 Win32 API 与 `HKCU` 注册表。
- 不申请管理员权限。
- 不引入安装器。
- 单进程、单线程、事件驱动。
