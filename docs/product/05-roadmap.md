# 路线图

> 状态：草案 v0.1 ｜ 更新：2026-11-01

## 1. 版本规划

### v0.1 — 最小可用（MVP）

范围：

- F-01 托盘左键切换
- F-03 模式选择（仅浅色 / 深色；Auto 全部留 v0.2）
- F-06 开机自启
- F-07 配置持久化
- F-08 单实例
- 深色右键菜单、单文件构建、基础日志

v0.1 明确**只做手动双态**：不实现自动模式、定时器、日出日落或任何目标时刻计算。v0.2 再做 F-04/F-05 与自动语义。

不含 F-02 全局热键切换（推迟至 v0.2）：v0.1 只保留托盘这一条手动切换入口，先验证"点击 → 写注册表 → 广播 → 刷新"的完整链路；热键的组合键解析与注册冲突处理在 v0.2 补齐。

托盘图标两套资产在 v0.1 一并交付，启动时按系统主题选定；运行中随系统主题刷新属于 F-11，在 v0.2 补齐。

退出标准：

- 在本机连续使用 3 天，不再打开系统设置切换主题。
- 冷启动 < 100 ms，常驻内存 < 10 MB，exe 体积保持轻量（记录实测值，不设硬性上限）。
- 无已知崩溃。
- 托盘左键在 Win10 / Win11 与 150% / 200% DPI 下均能完成切换。

### v0.2 — 自动化与打磨

范围：

- F-02 全局热键切换（P1，允许降级）
- F-04 固定时间调度
- F-05 日出日落调度
- F-09 状态提示
- F-10 高对比度保护
- F-11 托盘图标自适应
- "关于"与"打开配置文件"菜单项

退出标准：

- 自动切换连续 7 天无漏切、无重复切。
- 休眠唤醒补偿验证通过。
- 高对比度场景验证通过。
- 热键在目标环境可用；注册冲突时按 F-09 提示一次并降级为托盘切换。

### v0.3 — 编排与扩展

范围：

- F-12 仅切换应用主题
- F-13 主题编排（壁纸、强调色、外部命令）
- F-14 多语言
- 可选的设置窗口（替代手改配置文件）

退出标准：

- 编排动作失败不影响主题切换。
- 设置窗口在高对比度与 200% DPI 下可用。

| 渠道 | 说明 | 阶段 |
|---|---|---|
| GitHub Releases | 绿色 zip，主渠道 | v0.1 |

## 4. 度量与反馈

不做遥测，依赖：

- GitHub Issues 与 Discussions。
- 发布页下载量。
- 内测用户的定性反馈（是否替代了系统设置路径）。
- 本地日志（用户主动提供时才收集）。

关键问题清单（内测时问）：

1. 你第一次用的时候，知道要点哪里吗？
2. 自动切换有没有该切没切的时候？
3. 有没有哪次切换后，某些程序颜色没变？
4. 你会在什么情况下退出它？

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 微软在正式版推送原生快速设置开关 | 基础功能被系统覆盖 | 产品重心转向编排与自动化，基础切换保留为兼容层 |
| 部分应用不响应主题广播 | 用户感知"切了一半" | 文档说明 + 菜单提示；不采用重启 Explorer 的激进方案 |
| 热键冲突普遍（v0.2） | 热键不可用 | 降级为托盘切换，提示一次并支持修改配置 |
| 代码签名成本 | SmartScreen 拦截，下载转化低 | 使用低成本签名服务；未签名阶段在 README 说明 |
| 用户期望"换主题同时换壁纸" | 差评 | 路线图公开，v0.3 交付 |

## 6. 明确不做

- 主题包下载与分享。
- 按应用自动切换主题。
- 多用户 / 域环境策略。
- 系统托盘之外的常驻 UI（悬浮球、桌面挂件）。
- 自动更新程序（v1 之前只做"检查更新"跳转）。
