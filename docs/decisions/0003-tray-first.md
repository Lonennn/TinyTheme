# ADR-0003：以托盘为唯一常驻入口

> 状态：已接受 ｜ 日期：2026-11-01

## 背景

主题切换是高频、短时的操作。用户不希望为了切一次主题而打开一个窗口、等待界面加载、再关闭。任何主窗口都会带来启动成本、焦点抢占和额外的 UI 维护工作。

## 决策

- 常驻形态只有托盘图标，不创建可见的主窗口。
- 左键单击托盘图标直接切换主题，不经过菜单。
- 右键菜单承载模式选择与低频设置，菜单一屏可见，不使用二级子菜单。
- 设置通过配置文件对外暴露；设置窗口延后到 v0.3 评估。
- 不提供桌面悬浮球、桌面挂件、任务栏按钮等额外入口。

## 理由

1. 托盘是 Windows 上"常驻小工具"的默认位置，用户心智成熟。
2. 左键单击是最短路径，符合"一次点击"的产品原则。
3. 无主窗口意味着无窗口管理、无布局、无 DPI 适配负担，体积与内存都更可控。
4. 菜单只做选择，不做配置编辑，避免在原生菜单里塞入复杂控件。

## 后果

正面：

- 启动即用，不打断当前工作。
- UI 代码量小，测试面集中在菜单状态与图标状态。
- 与系统主题一致的原生菜单，视觉成本低。

负面 / 约束：

- 托盘图标可能被折叠进"隐藏的图标"，首次运行需要引导。
- 配置修改需要编辑文本文件，对普通用户不够友好。
- 无法承载复杂设置，v0.3 若引入编排功能需要额外的配置界面方案。

## 合规检查

- 不创建可见的顶层窗口（`ShowWindow` 仅用于菜单前置）。
- 菜单结构变更需同步更新 `docs/product/04-interaction-design.md`。
- 任何新增常驻 UI 入口都需要新开 ADR。
