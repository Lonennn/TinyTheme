# ADR-0002：零第三方依赖与单文件交付

> 状态：已接受 ｜ 日期：2026-11-01

## 背景

目标用户下载一个主题切换工具时，不愿意为它安装运行库、框架或安装器。任何额外的安装步骤都会显著降低首次使用转化率，也会增加卸载残留与安全审查成本。

## 决策

- 不引入任何第三方库；只链接 Windows 系统 DLL（`user32`、`shell32`、`advapi32`、`gdi32`、`dwmapi`、`shlwapi`）。
- C 运行库静态链接（`/MT`），不依赖 VC++ Redistributable。
- 配置使用系统自带的 INI API，测试使用单头文件库且只编译进测试目标。
- 交付形态为单个 exe，压缩包内附 README 与 LICENSE。
- 不提供安装器。

## 理由

1. 单文件是"轻量"最直观的表达，用户不需要理解依赖关系。
2. 没有第三方代码，许可证与漏洞面都最小。
3. 静态运行库避免了"缺少 VCRUNTIME140.dll"这类最常见的启动失败。
4. 绿色版可以直接放在任意目录，包括 U 盘与同步盘。

## 后果

正面：

- 解压即用，删除即卸载。
- 构建环境只需 VS Build Tools + CMake，CI 配置简单。
- 无依赖升级、无供应链攻击面。

负面 / 约束：

- 部分通用能力（JSON、日志、测试）需要自行实现或使用标准库。
- 静态运行库会带来少量体积增长，需要在编译选项中平衡。
- 未来若确需第三方库，必须新开 ADR 说明理由与体积影响。

## 合规检查

- CI 中执行 `dumpbin /dependents`，出现非系统 DLL 即失败。
- 发布前核对 exe 体积并与上一版本对比，明显膨胀需要说明原因。
- 测试依赖不得进入发布目标。

> 修订（2026-11-01）：体积目标改为"保持轻量"，取消 1 MB 阈值；核对方式改为版本间对比，不再作为发布门禁。
>
> 修订（2026-11-01）：项目目标不是"绝对零依赖"，而是**发布物小、无运行时依赖**。测试可使用 doctest 等只编译进测试目标的依赖；任何进入发布物的新依赖仍需新开 ADR。
